# Scope

Scope of this version. Build only what these use cases need; anything else is out of scope until this document changes.

## In scope

| # | Use case | Legacy source |
|---|----------|---------------|
| 1 | **Save daily attendance for a set of students**: one school, one date, a list of students with code, minutes late and notes. Updates the yearly absence summary and raises a chronic-absence alert at the threshold | `sp_SaveDailyAttendance` |
| 2 | **Retrieve attendance history for a student**: records for a school year (current year by default), newest first | `sp_GetStudentAttendance`, first result set |
| 3 | **Return chronic absenteeism status for a student**: total absences for the school year, threshold, and whether the student is chronically absent | `sp_GetStudentAttendance`, second result set |

Business rules, validation rules and known legacy bugs for these use cases are in [01.legacy-analysis.md](01.legacy-analysis.md).

## Out of scope

- Authentication and authorization
- Any user interface
- Printing and reports (Crystal report)
- Listing schools, grades, or the students to take attendance for (`sp_GetStudentsForAttendance`)
- Maintaining students, schools, terms or attendance codes (seeded by SQL script only)
- Resolving or notifying on alerts
- Migrating or cleaning existing data

## Guidelines

- Avoid overengineering: no features, endpoints, abstractions or configuration beyond the three use cases.
- When an ambiguity in the analysis affects a use case, pick the simplest reasonable behavior and record it in [decisions.md](decisions.md).
