# Implementation Plan

How the port gets built. It covers only the three use cases in [0.scope.md](0.scope.md), follows the [project rules](../.claude/rules/), and fixes the legacy defects in [01.legacy-analysis.md](01.legacy-analysis.md). Finding IDs (`R-n`, `V-n`, `BUG-n`, `AMB-n`, `SEC-n`, `MIS-n`) refer to that analysis, and decision numbers (`#n`) refer to [decisions.md](decisions.md).

## 1. Goals

| # | Use case | Endpoint | Legacy source |
|---|----------|----------|---------------|
| UC1 | Save daily attendance for a set of students | `PUT /schools/{schoolId}/attendance/{date}` | `sp_SaveDailyAttendance` |
| UC2 | Retrieve a student's attendance history | `GET /students/{studentId}/attendance` | `sp_GetStudentAttendance`, result set 1 |
| UC3 | Return a student's chronic absenteeism status | `GET /students/{studentId}/absence-summary` | `sp_GetStudentAttendance`, result set 2 |

Plus `GET /health` for the container orchestrator. Nothing else is built: no UI, auth, student lists, master-data maintenance, alert resolution or reports.

## 4. Database

`legacy/Database/schema.sql` stays the source of truth for the five existing tables. Docker compose mounts it read-only, and new scripts only add to it.

**01-missing-tables.sql** (#22, #29, #30):

| Table | Columns |
|-------|---------|
| `Schools` | `SchoolID INT IDENTITY PK`, `SchoolName VARCHAR(100) NOT NULL`, `Active BIT NOT NULL DEFAULT 1`, `AbsenceAlertThreshold INT NULL`, `TimeZone VARCHAR(64) NOT NULL DEFAULT 'UTC'` |
| `SchoolTerms` | `TermID INT IDENTITY PK`, `SchoolID INT NOT NULL`, `SchoolYear VARCHAR(9) NOT NULL`, `TermName VARCHAR(50) NOT NULL`, `StartDate DATE NOT NULL`, `EndDate DATE NOT NULL` |
| `AttendanceSubmissionLog` | `SubmissionID INT IDENTITY PK`, `SchoolID INT NOT NULL`, `SubmittedDate DATETIME NOT NULL`, `AttendDate DATE NOT NULL`, `RecordCount INT NOT NULL`, `SubmittedBy VARCHAR(100) NULL` |

**02-integrity.sql** (pending, #23):

| Change | Why |
|--------|-----|
| Drop `UQ_Summary`; add unique `StudentAttendanceSummary (StudentID, SchoolID, SchoolYear)` | Per-school summaries (#36) |
| Unique index `StudentAttendance (StudentID, AttendDate)` | One record per student per day (BUG-6, V13); also serves history date-range queries (BUG-15) |
| Filtered unique index `StudentAlerts (StudentID, SchoolID, SchoolYear, AlertType) WHERE ResolvedDate IS NULL` | One open alert under concurrency (#37) |
| Index `SchoolTerms (SchoolID, SchoolYear) INCLUDE (StartDate, EndDate)` | School-year range lookups (#30) |
| `RowVersion ROWVERSION` on `StudentAttendance` and `StudentAttendanceSummary` | Detect true races (#41) |
| Foreign keys to `Schools`, `Students`, `SchoolTerms`, and `StudentAttendance.AttendCode → AttendanceCodes.CodeValue` | Referential integrity and scaffolded navigations; history can't hide unknown codes (BUG-8) |
| `CHECK (MinutesLate >= 0)`, `CHECK (EndDate >= StartDate)` | Backstops for the domain rules |

**03-reference-data.sql** (#24): `P` Present; `A` Absent (absent); `E` Excused absence (absent, excused); `L` Late (present).

**04-demo-data.sql** (pending, #23): two schools in different time zones (one with a null threshold), terms for two school years, and a few students with synthetic names only.

The legacy procedures are not deployed (pending, #23). Their logic is ported to LINQ, and `sp_SaveDailyAttendance` cannot be created as written (BUG-4).

## 5. Design

### Domain

| Type | Kind | Responsibility |
|------|------|----------------|
| `SchoolYear` | Value object | A validated `YYYY-YYYY` name, where the second year is the first plus one (V9), plus the date range `School` resolves for it |
| `School` | Aggregate root | `IsActive`, `TimeZone`, the effective threshold (10 when null, R7), and its terms. `Today(TimeProvider)` returns the local date (#28, #29). `SchoolYearOn(date)` returns the year whose range contains the date, or none (#30, #31). `CurrentSchoolYear(today)` returns the latest year started on or before today (#32). `TermOn(date)` returns the containing term, with the earliest start winning on overlap, or none (R5, #33) |
| `Student` | Aggregate root (read-only here) | `Id`, `SchoolId`, `IsActive`; used for ownership checks (#34) |
| `AttendanceCode` | Aggregate root (reference) | `Value`, `IsAbsent`, `IsExcused`, `IsActive` (R23) |
| `AttendanceRecord` | Aggregate root, one per student and date | `Record(...)` creates and `Revise(...)` updates the code snapshot, minutes late, notes, school, term and audit fields (R2, R16, #39). Revising also corrects the school and term (BUG-9). Guards minutes late and notes (#40, V8) |
| `AbsenceSummary` | Aggregate root, one per student, school and year | `TotalAbsences` and the open `ChronicAbsenceAlert`. `Recalculate(total, threshold, now)` updates the total and raises at most one alert with the legacy message (R6–R8, R18, R19, #36–#38) |
| `AttendanceSubmission` | Entity | Audit row with the record count (R20) |
| `DomainException` | Exception | Invariant violations; the global handler maps it to `400` |

Each student's record and summary is its own object, so no state leaks from one student to the next (BUG-1, BUG-2).

### Application

- `SaveDailyAttendance` command handler (UC1):
  1. Load the school with its terms. Return `404` if it is missing and `400` if it is inactive (#35), if the date is after the school's today (#28), or if no school year covers the date (#31).
  2. Load the batch's students, the codes used, the existing records for the date, and the summaries for that school and year, each in one set-based query (no N+1).
  3. Validate ownership and codes (#26, #34), collecting every error before returning `Validation`.
  4. Record or revise each `AttendanceRecord`.
  5. Count each student's absences at that school within the year's date range, excluding the date being saved, in one grouped query. Add the new record's `IsAbsent` and call `AbsenceSummary.Recalculate`. This includes the pending changes without saving twice.
  6. Add the `AttendanceSubmission`, then call `IUnitOfWork.SaveChangesAsync` once, which runs in a single transaction (BUG-5).
  7. Log `"Attendance saved for {SchoolId} on {AttendDate}: {RecordCount} records, {AlertCount} alerts raised"` and return the per-student results (#43).
- `GetStudentAttendanceHistory` query (UC2): resolves the default year from the student's current school (#32), then `IAttendanceHistoryQuery` returns one page across all schools (#44, #45), newest first (R10, R21).
- `GetStudentAbsenceSummary` query (UC3): defaults to the student's current school (#46) and returns zeros when no summary exists (#47).
- `Result` / `Result<T>` with `NotFound`, `Validation` and `Conflict` errors, the one shared result type.
- `PageRequest` (validated `page`/`pageSize`, defaults and cap) and `PagedResult<T>` (`items`, `page`, `pageSize`, `totalCount`), shared by every list query (#50). An `IQueryable` extension in Infrastructure applies `Skip`/`Take` after the ordering and runs the count.
- Request/response `record` DTOs, and a Mapperly mapper for domain to DTO.
- Ports: one repository interface per aggregate (in Domain), plus `IUnitOfWork`, `IAttendanceHistoryQuery` and `IAbsenceSummaryQuery`.

### Infrastructure

- Scaffolded `AttendanceDbContext` and entities (§4).
- Repositories with a Mapperly mapper between entities and domain objects, building aggregates through their constructors or factories.
- Read queries use `AsNoTracking()` and Mapperly `IQueryable` projections. History joins each record to its own school's year range: `SchoolTerms` grouped by `(SchoolID, SchoolYear)` into minimum start and maximum end dates. It also joins the code description and term name.
- `IUnitOfWork` over the `DbContext`. `DbUpdateConcurrencyException` and unique-key `DbUpdateException` become a `Conflict` result (#41).
- `AddInfrastructure(IConfiguration)` registers the scoped `DbContext` and repositories.

### Api

- `SchoolAttendanceEndpoints` (`/schools` group) and `StudentEndpoints` (`/students` group), one file per resource. Each is a `MapGroup`, so `RequireAuthorization()` can be added in one place later (#14).
- One `ToHttpResult()` extension maps `Result` errors to `404`/`400`/`409` `ProblemDetails`.
- A global `IExceptionHandler` returns `500 ProblemDetails` with a `traceId` and maps `DomainException` to `400`. Responses never include exception details (SEC-8).
- `AddProblemDetails`, boundary validation of request DTOs, OpenAPI (`MapOpenApi`) with response types on every endpoint, HTTPS redirection and HSTS, CORS with origins from configuration (none by default), `AddHealthChecks().AddDbContextCheck<>()` at `/health`, and HTTP request logging with trace ids. JSON logs go to stdout.
- `TimeProvider.System` is registered as a singleton and replaced in tests.
- Configuration comes only from `appsettings` plus environment variables: `ConnectionStrings__Attendance`, `Attendance__AuditUser`, `Cors__AllowedOrigins`. User-secrets supply local values.

### API contract

**UC1: `PUT /schools/{schoolId:int}/attendance/{date}`**

Request:

```json
{ "entries": [ { "studentId": 12, "code": "A", "minutesLate": 0, "notes": "Called in sick" } ] }
```

Response `200`:

```json
{
  "schoolId": 3, "date": "2026-03-02", "schoolYear": "2025-2026", "threshold": 10,
  "students": [ { "studentId": 12, "totalAbsences": 10, "isChronicallyAbsent": true, "alertRaised": true } ]
}
```

| Rule | Response |
|------|----------|
| `date` is `yyyy-MM-dd` | `400` |
| `entries` has at least one item and no duplicate `studentId` (V4, #48) | `400` |
| `studentId > 0`; `code` is required and 1–5 characters; `minutesLate` is 0–600; `notes` is at most 500 characters (#25, #40, V8) | `400` |
| School missing | `404` |
| School inactive; date after today in the school's time zone; date outside every school year (#28, #31, #35) | `400` |
| Student missing, inactive or in another school; code unknown or inactive (#26, #34) | `400`, with errors keyed `entries[i].field` |
| True race (#41) | `409` |

**UC2: `GET /students/{studentId:int}/attendance?schoolYear=2025-2026&page=1&pageSize=50`**

Returns `200` with `{ items: [{ date, schoolId, code, codeDescription, isAbsent, isExcused, minutesLate, notes, termName }], schoolYear, page, pageSize, totalCount }`. Returns `404` for an unknown student, and `400` for a malformed `schoolYear` or out-of-range paging values.

**UC3: `GET /students/{studentId:int}/absence-summary?schoolYear=2025-2026&schoolId=3`**

Returns `200` with `{ studentId, schoolId, schoolYear, totalAbsences, threshold, isChronicallyAbsent }`. Returns `404` for an unknown student or school.

## 6. Testing

TDD throughout: red, green, refactor, and no production code without a failing test first. Each use case ships with unit and integration tests.

| Level | Project | What |
|-------|---------|------|
| Unit | `Domain.Tests` | `SchoolYear` parsing; `School` (today in different time zones, year from terms including breaks, no year, current year in the summer gap, term overlap); `AttendanceRecord` invariants and revision; `AbsenceSummary.Recalculate` (below, at and above the threshold; existing open alert; after a resolved alert) |
| Unit | `Application.Tests` | Handlers against in-memory fakes: all validation errors collected, ownership, counts that include the pending record, one save per command, not-found and conflict paths |
| Integration | `Api.IntegrationTests` | `WebApplicationFactory` with a Testcontainers SQL Server initialized from the same scripts as compose (`legacy/Database/schema.sql` plus `db/scripts/00–03`), with data seeded per test and a fake `TimeProvider`. Asserts status codes, `ProblemDetails` shape and persisted rows |

**Legacy parity and bug-fix cases** (integration level unless noted):

| Case | Expectation |
|------|-------------|
| R2 / R16 resave | Updates the row, keeps the creation audit and sets the modification audit |
| BUG-1 / BUG-2 | In a batch with an existing record followed by new students, each student gets their own row and their own code flags |
| BUG-3 / #30 | Absences from another school year are not counted; a date in a term break counts toward its year |
| #36 transfer | Absences at a previous school don't count toward the new school's summary |
| R7 / R8 / R19 / #37 | Reaching the threshold raises one alert with the legacy message; saving again above the threshold raises none; a null threshold means 10 |
| R5 / #33 | Term assigned from the date; null in a break; earliest start wins on overlap |

## 7. Containers

- `Dockerfile`: multi-stage build (the SDK image restores and publishes; the `aspnet` image runs; tests run outside the image build, #62), a non-root `app` user, and a `HEALTHCHECK` on `/health`.
- `docker-compose.yml`:
  - `db`: SQL Server (pinned tag) with a health check and a named volume.
  - `db-init`: runs `db/init.sh` with `sqlcmd` once `db` is healthy. It mounts `legacy/Database` and `db/scripts` read-only and skips the scripts if the database already exists.
  - `api`: starts after `db-init` completes, with its connection string from `.env` (`.env.example` is committed).
- `docker compose up` runs the whole stack. Integration tests use Testcontainers directly.

## 9. Out of scope (reminder)

Authentication, UI, printing, student lists (`sp_GetStudentsForAttendance`), maintaining students, schools, terms or codes, alert resolution or notification, and migrating or cleaning existing data (MIS-11). Production data with duplicate `(StudentID, AttendDate)` rows, or with no `SchoolYear` on terms, would need cleanup before go-live. That is a follow-up, not part of this version.
